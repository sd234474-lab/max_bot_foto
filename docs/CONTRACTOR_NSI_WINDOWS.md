# НСИ подрядчика Transport MAX — локальная проверка

Рабочая ветка: `codex-max-001-nsi`. Стенд находится внутри этой рабочей
копии; общий АРМ и его Центр запуска не используются и не изменяются.

## Запуск и остановка

1. Дважды щёлкните `START_CONTRACTOR.cmd` в корне репозитория.
2. Откройте адрес, напечатанный при запуске. Базовый адрес —
   `http://127.0.0.1:5174`. Рабочее пространство имеет путь
   `/org/<organization_id>/contractor/vehicles`.
3. Войдите с логином `contractor-admin`. Случайный локальный пароль и
   `organization_id` находятся в **локальном** `.local/config.json`.
   Не пересылайте этот файл и не добавляйте его в Git.
4. Для остановки дважды щёлкните `STOP_CONTRACTOR.cmd`.
   Данные сохраняются. Повторный запуск не сбрасывает БД и не импортирует
   источники автоматически.

Штатные команды Transport MAX: backend `python -m uvicorn app.api:app`,
frontend `node node_modules/vite/bin/vite.js`. Обёртка задаёт loopback-адреса,
порты 8014/5174 и отдельный конфиг. PostgreSQL слушает только
`127.0.0.1:55432`; база называется `contractor_max_test`. Состояние
процессов — `.local/processes.json`, журналы — `.local/logs/`.
Пароли и внешние токены из существующих `.env` не наследуются.
Receiver, worker, publisher, trainer и внешние интеграции не запускаются.

Центр запуска общего АРМ проверен на чтение: он использует SQLite,
`OperatorWebApp` и `wsgiref`, тогда как Transport MAX требует
PostgreSQL/PostGIS, FastAPI и React/Vite. Для этого стенда Центр не является
зависимостью. Никакой адаптации общего АРМ не выполнялось.

## Что проверить владельцу

- Откройте «НСИ подрядчика»: списки, поиск по имени/ID, фильтр состояния,
  отдельные карточки и ссылки между ними.
- В карточке контрагента проверьте реквизиты, контакты/полномочия,
  банковские счета, документы и технику. Оригиналы документов открываются
  из неизменяемых архивов, с проверкой SHA-256, без распаковки на диск.
- Проверьте цепочку территория АРМ → договорная территория → клетка →
  связь Wialon; связи геозон MAX находятся в отдельном справочнике и
  автоматически не создаются.
- Проверьте DO → PL → МАФ, договоры и две исходные редакции, документы
  ОП/РЦ и их строки. Количества и цены хранятся без перерасчёта.
- Откройте машину без имени: временная подпись содержит госномер,
  состояние — «Требует заполнения». Укажите и утвердите рабочее имя.
- Кандидатная связь с контрагентом не означает юридического собственника.
  Кнопка утверждения операционного владельца начинает новую связь
  сегодняшней датой и закрывает прежнюю; историю не переписывает.
- Подтверждённую договорную редакцию нельзя редактировать. Для подтверждения
  необходимы даты подписания/действия, основание и снимки обеих сторон.
  Новое соглашение создаётся отдельной редакцией.
- Оператор может просматривать НСИ; сервер отклоняет попытки записи.

Пользовательская приёмка завершается только после проверки владельцем.

## Источники и повторная загрузка

ZIP-анкетам соответствует каталог `../questionnaires` за пределами Git.
Локальные снимки прочитанных листов и договорных приложений находятся в
игнорируемом `.local/sources/`; оригинальные XLSX приложений имеют имена
`<Drive ID>.xlsx`. Они используются только для первоначального наполнения.
Исходные документы Drive не меняются и не синхронизируются с БД обратно.

Для повторной загрузки уже согласованного пакета:

```cmd
backend\.venv\Scripts\python.exe ops\contractor_local.py import
```

Загрузчик не заменяет существующие карточки и утверждённые данные.
Спорная строка не блокирует остальные. Технические результаты и причины
сохраняются в `nsi_import_events`; самостоятельной сравнительной формы нет.
Результаты различают ACCEPTED, LINKED, REVIEW и REJECTED.

Ограничения текущего пакета: сканы требуют визуальной сверки; два номера
Халилова неоднозначны; его числовые банковские счета не принимаются как
точные строки. Часть БИК в анкетах введена числом и требует сверки ведущего
нуля. Даты/снимки сторон договоров, полный текст контрактов и прочие
приложения не выдумываются. Юридический профиль Шашко остаётся незаполненным.
Черновые справочные значения сохраняют статус проверки. Подтверждающие
документы до сверки связаны с контрагентом, а не автоматически с машиной.

## Воспроизведение окружения

Установка зависимостей и создание новой БД требуют отдельного разрешения.
Уже созданный стенд не нужно переустанавливать.

- Python 3.12+; зависимости из `backend/pyproject.toml` и
  `ops/requirements-contractor-local.txt` в `backend/.venv`.
- Node.js; `npm ci` в `frontend`, `npm run build` для проверки сборки.
- Переносимые PostgreSQL 17 и PostGIS в `.local/runtime/pgsql`.
  Бинарные пакеты: [PostgreSQL Windows](https://www.postgresql.org/download/windows/)
  и [PostGIS Windows](https://postgis.net/documentation/getting_started/install_windows/released_versions/).
- После явного разрешения создание **нового** стенда:
  `backend\.venv\Scripts\python.exe ops\contractor_local.py init`.
  Повторная инициализация готовой БД запрещена; автоматического удаления нет.

Проверка кода без доступа к производственной БД:

```cmd
set PYTHONUTF8=1
cd backend
.venv\Scripts\python.exe -m pytest -q
```

Без `TEST_DATABASE_URL` общие PostgreSQL-интеграционные тесты пропускаются.
**Не задавайте им адрес наполненного стенда:** штатная общая фикстура
Transport MAX удаляет схему тестовой БД. Новые тесты НСИ используют
синтетические данные и изолированную БД в памяти.
